Atomic Heart

Developer

Feb 20, 2023

Atomic Heart is a first-person shooter in an alternative soviet setting developed by Mundfish studio.

As a technical designer I was in charge of prototyping, developing, iterating, polishing, bug fixing, and optimization of gameplay systems, player abilities, and interactive content on levels.

Contents

    Art, animation, UI, VFX, writing, audio, and engine code were created by the team. My part is the gameplay design and implementation described below.

    Ecosystem

    A system that allows the player to disable all cameras and robots in the current region for some time. Disabled robots will re-activate upon taking damage.

    I took over an old, non-working prototype built as one huge Blueprint. I brought it to a working state, restructured it, and moved the heaviest parts of the logic, such as searching for enemies, iterating over them, and checking which region they belong to, to C++. The real-time logic ran on a timer every few seconds instead of Tick, so it didn't load every frame.

    The main challenge was level streaming. The open world is never fully loaded at once, so the Ecosystem state lived in a subsystem that isn't unloaded together with levels. Whenever a sublevel streamed in, every enemy on it queried the subsystem for its status and behaved accordingly. The state was also saved and correctly restored on loading a save.

    Each Ecosystem region was an actor placed on the level, with a configurable radius and other parameters. I also built a debug mode that showed region radii and each enemy's connection status above its head, so level designers had everything they needed to set up and verify regions on their own.

    Jumping out of the car

    The player's ability to jump out of the car while it's in motion, built as a GAS ability. The result depends on speed: at very low speed the car stops and the player simply gets out, at medium speed the player jumps out and falls without rolling, and at high speed they fall into a roll, as in the video. I also extended the car's code so it keeps rolling by inertia after the player leaves.

    I worked closely with the animator on the blend and the sense of momentum. Root motion drives the character from the seated pose until they separate from the car; after that, the code takes over and positions the character based on a downward trace.

    As the door starts to open, a sphere trace checks a few meters ahead to make sure there is room to land. If the way is blocked, the ability is canceled: the door opens just slightly and the animation plays back, so the player sees the input registered and stays in the car. Otherwise, a downward capsule trace finds the landing height, so the character never gets stuck on uneven terrain, and the camera and hands don't clip through the ground.

    Zipline

    An interactive rope that allows the player to slide from start to finish.

    I implemented it as a Gameplay Ability System (GAS) ability that blocks many other player abilities while active, so nothing interferes with the slide.

    New Game +

    A "New Game +" mode where the player is allowed to replay the game's story while retaining abilities, resources, and upgrades accumulated in the first playthrough. This mode introduces tougher versions of enemies with new abilities.

    My part was mainly the enemy side. I built a dedicated component that is added to enemies automatically when they spawn. It defines their modifiers, upgrades, color indication, and so on, all configured through Data Assets. This keeps the base character class clean and lets the same setup move freely between characters of different classes and archetypes.

    Level Scripting

    Scripting of interactive content on levels: events, triggers, doors and mechanisms, puzzles, and combat encounters.

    Optimization

    Profiling and optimization of gameplay code in Blueprints and C++, UI, and level content. A lot of this work meant moving logic from Tick to event-driven updates.

    For example, one location had many rotating mixers with attached damage components, and they cut the frame rate in half: every frame, the engine recalculated overlaps for all of their moving collision. I replaced the collision-based damage with a math check that runs on Tick only for the mixer the player is near. After that, the mixers had no noticeable impact on performance.

    Release Stabilization

    Bug fixing and polishing before release in close collaboration with QA, followed by post-release patches. A large part of this work involved the save system: making sure every interactive element on levels saved its state and restored it correctly when a save was loaded.
